Study write-up · Experiential Learning Harness

Can AI agents become more experienced?

A frozen local coding agent fixes generated performance bugs. Four groups differ only in what they carry between tasks: nothing, a memory bank, a memory bank with learned ranking, or a memory bank with ranking and validated procedures.

Summary
  • Memory raises the pass rate on bugs the baseline fails. On quadratic_membership tickets over three learning histories (experiment 13), the no-memory baseline (A) fixed 6 of 36 test tickets, memory with rules (B) 26 and B with MemRL ranking (C) 23. Paired against A: B 21 wins, 1 loss; C 18 wins, 1 loss (McNemar p < 0.001 for both). B used 0.21× A's GPU time per success (95% CI 0.07–0.35).
  • The gain depends on what the first training tickets teach. B fixed 11, 12 and 3 of 12 test tickets in the three histories. In the third, no stored rule mentioned the ticket's second slow lookup, and the agent fixed only the first.
  • MemRL ranking does not improve on plain memory. B against C in experiment 13: 6 wins, 3 losses (p = 0.51). Across experiments 10, 11 and 13, B fixed 46 of 60 and C 43 of 60.
  • Where the baseline already succeeds, memory reduces cost but not failures. On nested_scan_join (experiment 12), A fixed 9 of 12, B 9 and C 10. C used 0.67× A's GPU time per success (95% CI 0.44–0.93). On the easy queue_pop_front bug (experiment 6), the memory groups did worse than A.
  • Validated procedures (D) did not improve on C in the one run that included them (D 10 of 12, C 12 of 12).
  • Memory does not prevent protected-file overwrites. Agents with memory still overwrote examples/sample_output.json, including after a rule naming the file was stored.

Design

Test groups

All groups use the same model, prompt, tools, sandbox, budget (40 turns, 600,000 tokens) and judge. Memory is shown once, in the first message of an episode. Test episodes read a frozen snapshot of the memory.

Methods

Methods and deviations

Each group implements the method of a paper cited in the proposal, taken from the paper and its released code. Deviations are listed.

Hindsight

Latimer et al., ACL 2026 demo · arXiv 2512.12818
Method
Memory typed as world facts, experiences and observations, with retain, recall and reflect. Recall fuses semantic, keyword, graph and temporal search, then reranks with a cross-encoder.
Implementation
Record format lesson-v3: a one-sentence outcome context without ticket text, tagged by outcome and failed checks. Recall is limited to experience facts. Every recall logs its ranked candidate list. elh/memory/hindsight.py
Deviations
reflect is not called during episodes (43 s and about 44,000 tokens per call).

MemRL

Zhang et al., arXiv 2601.03192
Method
Two-phase recall: keep memories above a similarity threshold, take the top k1, rank by 0.5·z(similarity) + 0.5·z(Q), inject the top k2. After each episode, Q ← Q + 0.3(r − Q) for every injected memory. Reported gains on fresh coding tasks are 1–2 points.
Implementation
Reranks Hindsight's candidate list, with Q kept per source episode. Test episodes use a frozen copy of Q. elh/learner/utility.py
Deviations
Failure reward is −1 (as in MemRL) rather than the spec's 0, under which Q could never fall. The similarity threshold is the 20th percentile of our candidate similarities (0.838 on hard tickets), because Hindsight has already filtered the candidates. The threshold calibrated on quadratic_membership was reused for nested_scan_join.

Learning on the Job

Tablan, Taylor & Bernhem, arXiv 2607.22157
Method
After each episode the agent writes one rule: "VERIFIED RULE: WHEN … THEN …" after a pass, "AVOID: …" after a failure, with a query field used for retrieval. A validator rejects rules that omit key facts. The agent searches memory itself during the task.
Implementation
The paper's reflection and rejection prompts, adapted to tickets. The rule writer sees the judge's per-check verdict but never the hidden tests or reference fix. Rules are stored verbatim (no LLM extraction) and take the first two memory slots. elh/learner/rules.py
Deviations
With no gold solution, the validator only requires protected-file names. Merging conflicting rules is not implemented.

Agent Workflow Memory

Wang et al., ICML 2025 · arXiv 2409.07429
Method
Induces reusable workflows from successful runs and regenerates the library after each success.
Implementation
AWM's induction prompt with three domain substitutions, run on passed training episodes. Libraries are versioned with their source episodes. elh/learner/workflows.py
Additions
The proposal requires validation, which AWM does not have. A candidate library is promoted only if, on 6 development tasks run twice each, mean reward rises, passes do not fall and protected-file breaks do not rise.

GEPA

Agrawal et al., ICLR 2026 · arXiv 2507.19457
Method
Evolves text by reflecting on rollouts and feedback, keeping candidates on a Pareto frontier across validation tasks.
Implementation
Adapter for the gepa package that optimises group D's procedure text on development tasks only. elh/learner/gepa_opt.py
Deviations
The reflection prompt asks for general procedures instead of "niche domain facts". Merge is off. Not yet run in an experiment.

When Continual Learning Moves to Memory

Hu, Long & Wang, arXiv 2604.27003
Method
Splits test tasks by whether the baseline solves them. ΔRR measures solved tasks that memory breaks; ΔNL measures failed tasks that memory solves. Also forward and backward transfer.
Implementation
ΔRR, ΔNL (withheld below 10 baseline failures, as in the paper), transfer, hold rate, paired cluster bootstrap and recall diagnostics. elh/analysis.py

Experiment 13 · three histories

Memory's gain holds across histories; its size depends on the first lessons

Groups A, B and C, run three times on the same 15 training and 12 test tickets. Each history shuffles the training order and starts from empty banks.

B against C: 6 wins, 3 losses (p = 0.51).

The tickets contain two slow list lookups, the seen list and a second list such as blocked. In histories 1 and 2, 31 of 60 stored rules mentioned the second lookup; in history 3, 0 of 30 did. In 45 of history 3's 47 timeouts, the agent had replaced seen with a set and left the second list unchanged. The timing check was stable across histories (reference median 0.14 s in each), and agent code either matched the reference or timed out at about 20×.

The 12 test tickets are shared across histories, so the bootstrap clusters by ticket. Three histories show that outcomes vary by history but do not estimate how often an incomplete lesson occurs.

Experiments 10 and 11 · verbatim rules

B and C both beat A; their order reversed between runs

Paired against A, C won 8 and lost 0 in experiment 10 (p = 0.008); B won 9 and lost 0 in experiment 11 (p = 0.004). Pooled, B and C each fixed 20 of 24 against A's 7. In experiment 11, C passed 9 of 15 training tickets and B 15 of 15, so the group with the weaker training run had the weaker bank at test time.

D tried three AWM procedures in experiment 10. The check rejected the first (dev-panel passes fell from 7 to 5 of 12), promoted the second (7 to 9) and rejected the third (12 to 12). Its 72 development episodes cost 2,877 agent GPU seconds, charged as learning.

Experiments 8a and 8b · hard tickets, before verbatim rules

Memory helped on hard tickets before the rules reached the agent

Pooled over both runs, B won 11 paired tickets and lost 3 (p = 0.057). With rules, B passed 10 of 15 training tickets against 4 of 15 without (Fisher p = 0.066). Hindsight's fact extraction had paraphrased every rule: none of 587 recall candidates in 8b contained rule wording. Rules have been stored verbatim since experiment 10.

Experiment 12 · second bug type

No pass-rate gain where the baseline succeeds

On nested_scan_join, all failures were protected-file breaks or wrong output, not slow code. Both memory groups used about 8 fewer turns than A. C's GPU time per success was 0.67× A's (95% CI 0.44–0.93); B's was 0.91× (0.54–1.58).

Experiments 1 and 6 · easy tickets

On an easy bug, memory did not help

Experiment 1 was voided: failed checks were recorded in the wording of the passing check, so memory stored that an attempt "failed because it left the tests and harness untouched". After that was fixed, A and B each passed 9 of 10. A protected-files lesson reached the top 5 in only 1 of 10 test episodes, because ticket text in the memory context made recall rank by ticket similarity. Restricting recall to experience facts raised this to 8 of 10 in a replay.

In experiment 6, B passed 6 of 10 and C 5 of 10, against A's 8. Both memory groups broke the protected-files rule 3 times, always by writing verification output over examples/sample_output.json, including immediately after recalling a lesson that named the file. C's recall returned the same top memory in 80% of test episodes.

Method notes

Harness fixes

Bugs found and fixed

  • Failed checks recorded in passing wording (experiment 1 voided).
  • Ticket text in the memory context made recall rank by ticket similarity.
  • A 500 KB scratch file in an episode diff caused about 40 memory-model calls; diffs now cover source files only.
  • The spec's reward for group C could never demote a memory.
  • Rules paraphrased by Hindsight's fact extraction; experiment 9 was stopped after 6 episodes.

Safeguards

  • Model and memory LLM pinned by weights hash, checked before every episode.
  • Test episodes must leave the memory snapshot's content and learner hashes unchanged.
  • Learners never see hidden tests or the reference fix; tests check this.
  • Earlier experiment configs keep their hashes, so old runs reproduce.
Limitations

Limitations

  • 10 or 12 test tickets per group per history. At a 90% pass rate, the 95% interval spans about 60–98%.
  • Only experiment 13 has more than one history. Its histories ranged from 3 to 12 of 12 for the same group, so single-history results carry similar variation.
  • Costs use placeholder prices. Cached input, about 97% of input tokens, is priced at zero. Measured GPU time puts learning at 80–90% of inference cost; the ledger says 28%.
  • Published effects for these methods are a few points on fresh tasks. The confirmatory study needs a power analysis based on pilot variance.
Decisions

Open decisions

  1. Prices from GPU time. Replace placeholder prices with prices derived from measured GPU seconds. This changes the registration.
  2. Group C reward. Amend the spec to "pass: 1 − cost, fail: −1", or keep the spec's formula and report this one as a sensitivity analysis.
  3. GEPA development panel. With 6 tasks, only 1 is unseen by GEPA's search; a larger panel is needed.
  4. Reflect. Test Hindsight's reflect, or a standing mental model of past failures, as an ablation of B.
  5. Unit of analysis. Treat the learning history as the unit and run more histories, possibly in parallel, at the cost of comparable GPU-time measurements.
